Proposed Approach: Unified AmanClaw Design System

3 approaches ranked by how they sequence the work

★

Recommended: Layered Build-Out

Build the design system in layers, applying each layer across ALL apps before moving to the next. Every layer is a shippable improvement.

Layer 1 Design Tokens + Theme — CSS custom properties for colors (teal/gold/dark palette), typography scale, spacing, border radii. Tailwind config. Light/dark mode. Applied to all apps.
Layer 2 Icon System + Typography — Install Lucide, replace all Unicode/emoji icons, apply type scale. Instantly transforms every page.
Layer 3 Core Components — Button, Input, Card, Badge, Table, Modal, Toast using Bits UI + your tokens. Shared between Desktop & Dashboard.
Layer 4 Layout Components — Sidebar, TopBar, PageHeader, EmptyState, LoadingState. Unified navigation across Desktop & Dashboard.
Layer 5 Page-by-Page Polish — Rebuild each page using the component library. Desktop (17 pages) → Dashboard (11) → Chat → Landing → Playground.
B

Big Bang: Design System + Desktop Rewrite

Build the entire design system AND rewrite the Desktop app simultaneously. Ship one massive update. Other apps follow later.

Pros

  • Desktop gets full treatment immediately
  • Can test components in real context

Cons

  • Long time before anything ships
  • Other apps stay ugly for weeks
  • Hard to review massive PRs
C

Parallel Tracks

Design system in a shared package, each app redesigned in parallel by separate agents/branches.

Pros

  • Fastest wall-clock time
  • All apps improve simultaneously

Cons

  • Merge conflicts between branches
  • Components evolve differently per app
  • Hard to coordinate shared library changes

Why Layered (★) wins

Each layer is a complete, shippable improvement across ALL apps. After Layer 1+2 alone (tokens + icons), every app already looks noticeably better — you get early wins while building toward the full system. No big-bang risk, no merge conflicts, and the design system grows organically from real usage.
